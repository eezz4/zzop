# Extending zzop — where you plug in, in the order you hit it

Every other page here is organized around what zzop is. This one is organized around **where your
stack stops matching it**, because that is the order you actually meet these problems in.

The short version: zzop's built-ins are a starting point, not the product. What it knows about *your*
repository is what you declare. The table below is the whole surface, cheapest first.

| # | You notice | Where you fix it | Cost |
|---|---|---|---|
| 1 | Nothing is analyzed | you need a `zzop.config.jsonc` at all — [`zzop init`](getting-started.md) writes one | one command |
| 2 | Your files aren't parsed | [`parsers.globOverrides`](#2-your-files-are-not-parsed) | one config entry |
| 3 | Rules miss things they should catch | [`vocabulary.*`](#3-zzop-guesses-your-names-wrong) | one config key |
| 4 | The cross-layer join is empty or partial | [`trees[].topology`, `trees[].routes`](#4-the-join-is-empty-or-wrong) | config |
| 5 | A rule you want does not exist | [a DSL rule pack](#5-the-rule-you-want-does-not-exist) | a JSON file |
| 6 | A rule fires where it should not | [`rules.<id>`](#6-a-rule-is-wrong-for-your-repo) | one config line |
| 7 | zzop cannot read your language or framework shape at all | [an envelope adapter](#7-zzop-cannot-see-your-shape-at-all) | **you write code** |

**Steps 1–6 are declarations. Step 7 is a program.** That asymmetry is the honest shape of this tool:
*names* are cheap to teach it, *shapes* are not. If you are deciding whether zzop fits your stack,
that is the line to check first.

---

## 2. Your files are not parsed

zzop dispatches by file extension. A house extension, a generated suffix, or a template dialect it
has never seen simply gets no parser — and the symptom is quiet, because the file is still walked and
counted. Only the extracted facts are missing.

```jsonc
"parsers": {
  "globOverrides": [
    { "glob": "src/**/*.houseml", "language": "typescript" }
  ]
}
```

Checked before the extension map, first match wins. Languages: `typescript`, `python`, `java`,
`rust`, `go`, `csharp`, `sql`, `prisma`. Naming one this build does not have is a warning listing
what it does have — never a silent skip.

## 3. zzop guesses your names wrong

A rule that looks for an auth guard has to know what your project calls its auth guards. zzop ships
suggestions, and `zzop init` writes them into your file — but they are **yours to edit**, and an
undeclared key means that judgment is not made rather than guessed.

```jsonc
"vocabulary": {
  "authGuardPattern": "(?i)(requireAuth|withCorpAuth|ensureSession)",
  "routerNames": ["apiRoutes", "corpRouter"],
  "generatedFileMarkers": ["@generated", "AUTO-GENERATED BY codegen-x"]
}
```

Each key replaces its list or pattern outright — never an element-wise merge, so the effective set
always has one author. Keys you leave alone keep what `init` wrote. Nesting follows the same rule at
the leaf: declaring `vocabulary.fsd.entry` leaves the other three `fsd` keys untouched, exactly as
`packs.disabled` leaves `packs.extraDirs` alone.

**Watch the keys where "not judged" is the permissive direction.** For most of this block, leaving a
key alone costs you recall: an undeclared `authGuardPattern` means no name proves a guard. But a few
keys are veto or skip lists, where the same rule runs the other way — an undeclared `skipDirs` skips
nothing (your `target/` and `node_modules/` get walked), and an undeclared `fileReadCallees` makes
`cache-lane-file-read` silent on a tree that really has the defect. Both of those are what `zzop init`
writes for you; the trap is deleting a key you thought was optional. We hit both while writing this
repo's own config.

One key deliberately ships EMPTY, because there is nothing honest to default to:
`vocabulary.cacheLaneAnchorPattern` names the function that produces one cached per-file unit in *your*
codebase, and only you know which one carries that promise. Fill it in and `cache-lane-file-read` walks
the call graph from there, reporting any filesystem read it can reach — an input your cache key almost
certainly does not cover. Leave it empty and the rule makes no judgment at all.

## 4. The join is empty or wrong

The cross-layer join matches a caller's `GET /api/users` against a server's route of the same key. It
goes wrong in two ways, and both are declarations rather than code:

**A gateway rewrites paths.** Your backend serves `/users`, your frontend calls `/api/users`, and the
`/api` lives in an ingress zzop never reads.

```jsonc
"trees": [
  { "root": "./api", "sourceId": "api",
    "topology": { "mountedAt": "/api", "hosts": ["api.internal.example.com"] } }
]
```

**Your client's base path is real but unreadable.** `axios.defaults.baseURL = settings.baseApiUrl` — the
prefix exists on the wire, but zzop refuses to guess a value it cannot read at the assignment, so the calls
key `GET /articles` while the backend serves `GET /api/articles` and nothing joins. Declare it on the
CALLING tree (the mirror of `mountedAt`; `cross-layer/all-consumes-unjoined` is the finding that points
here):

```jsonc
"trees": [
  { "root": "./web", "sourceId": "web",
    "topology": { "clientBase": "/api" } }
]
```

If the base *is* a literal in the source, zzop already read it — declaring it again stacks a second copy,
and the run says so in a warning rather than silently keying `/api/api/...`.

**A route is not statically visible** — a computed path, a dynamic verb, a wrapper. Inject the fact
directly:

```jsonc
"topology": { "mounts": [{ "dir": "src/admin", "at": "/admin" }] },
"routes": [ { "key": "POST /webhooks/stripe", "role": "provide" } ]
```

## 5. The rule you want does not exist

Write a rule pack. **The packs zzop ships are the example** — they are the same format, read by the
same loader and checked by the same validator as yours, so
[`rules/dsl/http/http.json`](../rules/dsl/http/http.json) is a worked reference rather than a
simplified one. Point `packs.extraDirs` at your own directory (or drop packs in `zzop/rules/`, which
is discovered with no config at all), and machine-check the shape with `zzop validate-rule-pack`.

Matchers available: line scan (lexical regex), method scan, symbol scan and io scan (both IR
queries). Whole-graph and cross-layer questions stay native — a DSL pack cannot walk the call graph.
See [rules/authoring-guide.md](rules/authoring-guide.md).

## 6. A rule is wrong for your repo

```jsonc
"rules": {
  "typescript/no-explicit-any": "off",
  "sql/select-star": { "severity": "warn", "exclude": ["src/legacy/"] }
}
```

Per-rule severity, disabling, and path exclusion. `exclude` entries are path substrings, or globs
when they carry wildcards.

## 7. zzop cannot see your shape at all

Everything above teaches zzop **names**. This step is for when the *shape* is the problem: a language
with no parser here, a framework whose routes look like nothing zzop recognizes, a client wrapper
that hides every call.

The escape hatch is the **Normalized AST envelope** — you produce the facts, zzop joins and rules
them:

- **Mode A** (`zzop analyze-envelope`) — a full envelope standing in for a whole tree. Your parser,
  zzop's analysis.
- **Mode B** (`trees[].overlays`) — a partial envelope merged on top of native parsing. Fill one
  missing channel and leave the rest alone; this is almost always the cheaper answer. The channel need
  not be wholly missing: facts merge additively, so an adapter can supply just the imports or io the
  native parser could not resolve on a file it otherwise parsed fine. Where both sides speak about the
  same thing the native fact wins — an overlay adds, it never overrides.

Contract: [NORMALIZED_AST.md](NORMALIZED_AST.md), schema
[`adapters/envelope.schema.json`](adapters/envelope.schema.json), minimal example
[`contracts/example-envelope.json`](contracts/example-envelope.json), worked references and a shared
library in [`examples/adapters/`](../examples/adapters/README.md).

**This step costs real work, and we would rather you did not need it.** It is the honest boundary of
a tool that reads syntax without a type layer: when the facts cannot be read, they have to be
supplied. If you find yourself here for something common, that is worth reporting — the fix may
belong in the engine.

---

## What has no extension point, and why

- **Native parsers and framework recognizers** are ours to write. There is no plugin ABI, and adding
  one would mean a stable internal AST contract this project has deliberately not committed to. Mode
  A is the supported substitute.
- **Rule thresholds** (counts, limits) are not configurable. Severity and scope are; the numbers a
  rule computes with are not, because a threshold nobody can see is a finding nobody can explain.
- **Reports and output formats** — zzop emits JSON and a mermaid graph. There is no report renderer
  to configure.
